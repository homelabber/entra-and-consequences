## Schema and semantic decisions

- [Registration troubleshooting](https://learn.microsoft.com/en-us/entra/identity/authentication/howto-registration-mfa-sspr-combined-troubleshoot#audit-logs) distinguishes individual successful registration from completion, review, deletion and default-method changes. Sources use the display label “User registered security information.” The exported `OperationName` spelling was **not certified by raw tenant exports**. The shared fragment provisionally accepts `User registered security info` and `User registered security information` only. Capture representative successful individual registrations, verify raw labels and target structure, and amend the exact list if necessary. No broad `has 'security info'` match is used.
- [Audit activity reference](https://learn.microsoft.com/en-us/entra/identity/monitoring-health/reference-audit-activities) warns activity lists can change. Successful completion of all required methods is not treated as an individual-method-addition signal. Admin/service-mediated paths not represented by these exact operations are not claimed covered.
- [AuditLogs schema](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/auditlogs): target identity comes from the User target in `TargetResources`, not `InitiatedBy`. Directory joins use `AADTenantId`, not the workspace `TenantId`.
- [MicrosoftGraphActivityLogs schema](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/microsoftgraphactivitylogs): `AadTenantId` and `UserId` join delegated-user activity; blank users and app-only activity are excluded from S002. Read-only top-level `/v1.0/` or `/beta/` surfaces are counted separately per `AppId`. `/me`, batched inner requests, alternate URI representations and other APIs are not normalized in this version. Successful requests and resource sign-ins do not prove data exfiltration.
- [EntraIdSignInEvents schema](https://learn.microsoft.com/en-us/defender-xdr/advanced-hunting-entraidsigninevents-table): current table name, Entra P2 requirement, successful `ErrorCode == 0`, numeric risk values 50/100. D001 consumes at-sign-in risk, not every subsequently computed offline user risk.
- [CloudAppEvents schema](https://learn.microsoft.com/en-us/defender-xdr/advanced-hunting-cloudappevents-table): depends on Defender for Cloud Apps activity collection. D001 requires `Update user.`, successful AzureActiveDirectory workload, `User_GUID` targets, self-attributed actor/target equality and valid phone-app arrays. Strict matching intentionally fails closed rather than guessing identity. Microsoft reporting provides phone-app update examples, but tenant payload compatibility is still a required gate.
- [Custom-detection requirements](https://learn.microsoft.com/en-us/defender-xdr/custom-detection-rules): D001 preserves `Timestamp`, `ReportId`, and `AccountObjectId` from the same final CloudAppEvents source event. It does not substitute the target into an unrelated actor's entity field. Cross-tenant aggregated Defender data is not supported by this version.
- [Service-principal sign-in schema](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/aadserviceprincipalsigninlogs): H001 matches a ServicePrincipal audit target to initiating `ServicePrincipalId`, never a resource principal or an application object ID. `AppId` is a client/application ID, not an application object ID. The credential metadata change may be removal or rotation; subsequent sign-in does not prove use of a changed credential. Actual raw success values and credential property names need verification.

## Promotion/retirement policy

For each rule, record the exact native template/policy versions enabled, qualifying native alerts already present, extra evidence the correlation adds, necessary log plans/licensing, query results, reviewed legitimate workflows, owner and reassessment date. Do not infer absence from a missing `SecurityAlert` row. A product might detect in another portal, have delayed risk processing, lack export, or require a license.

Keep a rule hunting-only or disabled if it adds no investigation value. Retire redundant logic when Microsoft adds equivalent content. Match native incidents by identity, time and source evidence; do not suppress all native alerts because a custom correlation exists. This offline package cannot inventory your licensed/enabled native content or certify a nonduplication guarantee.
